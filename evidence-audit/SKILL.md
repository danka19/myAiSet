# Evidence Audit

Make substantial audits reproducible. Ordinary factual answers, focused verification, and small reviews do not require an audit artifact.

1. Define the target, criteria, evidence needed, severity scale, and limitations.
2. Inspect the canonical project context and relevant artifacts. Record observed facts separately from inferred causes and unverified suspicions.
3. Write one dated record in the established audit location. Use the user's output location for a projectless task. If neither exists, choose a conventional location within the authorized workspace; ask only when document ownership is consequential.
4. For each finding, include its identifier, classification/severity, impact, reproducible evidence, root-cause confidence, and recommended action. Do not invent missing measurements.
5. Summarize material findings and remaining uncertainty. Proceed with fixes already authorized for this scope; a read-only audit alone does not authorize implementation or external work items.

The audit owns observations. Specifications own proposed behavior; roadmap files own ordering; current-state docs own status. Link between them rather than copying every finding into each document.

Ask about remediation only when a real next decision is needed. Do not append a mandatory permission question to every report, repeat an approval already given, or create competing plans and task lists.

If tests/evaluations are excluded, use permitted inspection and state the evidence limit. Do not relabel a proposed optimization as a measured improvement.
